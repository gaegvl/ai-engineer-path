# 03. Промпты: формулировка = результат

## Теория (коротко)

**Prompt** — входной текст для модели.  
Качество ответа сильно зависит от того, *как* ты просишь.

Полезные приёмы на старте:

| Приём | Пример |
|-------|--------|
| Роль | «Ты — терпеливый преподаватель Python» |
| Цель | «Объясни X» / «Найди ошибки» / «Сравни A и B» |
| Формат | «Ответь списком» / «только JSON» / «таблица» |
| Ограничения | «Не больше 5 предложений» / «без воды» |
| Контекст | «Вот текст: … Опирайся только на него» |
| Примеры | Показать 1–2 образца желаемого ответа (few-shot) |

Плохой промпт: `расскажи про AI`  
Лучше: `Объясни junior-разработчику, чем LLM-приложение отличается от обычного CRUD API. 5 пунктов.`

**Prompt engineering** — умение стабильно получать нужный результат. Это часть работы AI Engineer, но не вся работа.

## Задания

Возьми одну тему, например: `что такое REST API`.

- [ ] Запрос 1: коротко и размыто — `что такое REST API`
- [ ] Запрос 2: с ролью и уровнем — `Объясни REST API человеку, который пишет Python-скрипты, но не делал веб.`
- [ ] Запрос 3: с форматом — `Дай определение REST API и таблицу: термин | смысл (5 строк).`
- [ ] Запрос 4: с ограничением — `Ответь ровно 3 предложениями. Без списков.`
- [ ] В journal сравни: какой ответ полезнее и почему.

Бонус:

- [ ] Попроси модель **улучшить твой промпт**:  
  `Улучши этот промпт для более точного ответа: "..."`  

## Проверка себя

1. Назови 3 рычага, которыми ты управляешь ответом.
2. Почему «будь полезным» часто хуже, чем конкретный формат?
